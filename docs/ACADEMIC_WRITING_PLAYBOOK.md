# Academic Writing Playbook

本文件用于治理本仓库的硕士论文长期写作方式。它只记录写作范式和审稿式自检规则，不替代正式论文正文，不替代真实技术文献引用，也不授权 Codex 自行改写 `chapters/`、`frontmatter/`、`backmatter/` 中的正文。

## 1. 总体论证链

全篇论文应维持一条连续论证链：

背景 -> 实际困难 -> 研究进展 -> 现有不足 -> 研究问题 -> 技术路线 -> 方法 -> 总体实验 -> 消融 -> 机制/可视化 -> 稳定性与效率 -> 局限。

每一节都应承担一个明确论证任务。若删除某一段不会影响上述链条，该段通常属于低信息密度内容，应删减、合并或改写。

## 2. 摘要写作规则

摘要不写成模型清单，应写成问题驱动的研究闭环。

- 开头先说明研究背景、应用价值和当前不足，避免长篇铺垫。
- 每项工作按“问题 -> 方法 -> 关键设计 -> 实验结果 -> 结论含义”的顺序展开。
- 若论文包含两个工作，摘要必须体现二者的递进或继承关系，不能只并列描述两个模型。
- 摘要中的强结论必须能在正文实验章找到对应证据。
- 涉及性能、效率、边界、稳定性、统计差异的表述，必须与 `docs/FACTS_AND_NUMBERS.md` 中的事实一致。
- 不在摘要中引入正文没有验证的泛化、临床适用性或工程部署结论。

## 3. 绪论写作规则

绪论应完成从现实问题到研究任务的推导。

- 先解释医学图像分割任务的应用背景和实际困难，再进入技术路线。
- 研究意义要落到具体约束，如小目标、边界模糊、类间不均衡、三维空间关系、参数量、推理速度、显存或部署限制。
- 研究现状之后必须自然推出“现有不足”，不足要能被后续方法和实验验证回应。
- “研究内容”不是摘要复述，而是论文路线图：说明每项工作解决什么问题、为什么需要该工作，以及后续工作如何承接或升级前一项工作。
- “论文组织结构”只说明章节承担的功能，不堆砌目录句。

## 4. 国内外研究现状组织规则

研究现状原则上按照技术路线和研究问题组织，禁止按作者年份简单罗列。

推荐组织方式：

- CNN/U-Net 及其改进：说明局部特征、跳跃连接、多尺度建模、编码器-解码器结构的作用和局限。
- 注意力、全局上下文或 Transformer 类方法：说明远程依赖、全局建模、局部细节保持和计算成本之间的矛盾。
- 多尺度、空洞卷积、密集连接、状态空间或混合结构：说明其试图解决的感受野、细节恢复、效率或结构表达问题。
- 2D 与 3D 方法：说明切片建模与体数据建模在计算复杂度、空间连续性、上下文完整性上的差异。
- 轻量化与实时分割：说明准确率、推理速度、模型规模和部署平台之间的取舍。

每一类方法都应回答：它解决了什么问题、采用了什么思路、仍留下什么不足、这些不足如何引出本文研究问题。

## 5. “本文主要研究内容”双工作递进规则

若论文包含两项主要工作，必须明确二者关系。本论文目标至少达到以下前两类之一，不能停留在“都是医学图像分割”的主题统一。

### 5.1 核心机制继承式

Work1 提出或验证核心机制 A，用于解决问题 P1。Work2 在 A 的基础上引入机制 B 或扩展应用条件，进一步解决问题 P2。此类关系最强，适合写成“提出 -> 扩展 -> 深化”的研究主线。

自检问题：

- Work2 是否继承了 Work1 的核心思想、模块机制或实验发现？
- Work2 的改进是否能解释为对 Work1 局限的继续推进？
- 两项工作是否共享一个可追踪的技术原则，而不仅共享任务名称？

### 5.2 问题层次升级式

Work1 解决较基础或较低维度的问题，Work2 面向更复杂、更高层级或更接近真实应用的困难。例如从 2D 切片分割进入 3D 体数据建模，从总体精度提升进入边界、小目标、稳定性或效率约束。

自检问题：

- Work2 是否来自 Work1 没有覆盖或暴露出的真实限制？
- 问题升级是否体现在数据形态、建模范围、实验难度或工程约束上？
- 章节衔接是否能解释为什么必须开展第二项工作？

### 5.3 仅主题统一式

两项工作只共享“医学图像分割”主题，但数据、机制、问题和实验证据彼此孤立。这种关系较弱，容易形成两篇小论文拼接感。若无法避免，应在第一章明确两项工作分别对应同一上层问题的不同瓶颈，并在总结中分别回收证据。

## 6. 第二章理论债务原则

第二章只偿还后续方法真正产生依赖的理论债务。

- 方法章使用 U-Net、编码器-解码器、跳跃连接或多尺度特征时，第二章应铺垫相关结构和概念。
- 方法章使用 Transformer、注意力、全局上下文或状态空间模块时，第二章应解释其建模动机、输入输出含义和适用限制。
- 方法章涉及 3D 医学图像时，第二章应说明体数据、切片、体素、patch 或空间上下文的基本概念。
- 实验章使用 Dice、IoU、HD95、ASSD、Params、FLOPs、推理时间或显存时，第二章或实验章应给出定义与评价意义。
- 不使用的理论不应铺成长篇教材内容。

## 7. 方法章写作规则

### 7.1 方法章引言

方法章引言按以下链条组织：

前文不足 -> 当前具体困难 -> 总体思路 -> 关键设计 -> 本章贡献。

引言要先说明“为什么需要本章方法”，再说明“方法由什么组成”。不要一开头就罗列模块名称。

### 7.2 方法主体

方法主体按以下顺序组织：

总体架构 -> 数据流 -> 核心模块 -> 数学表达 -> 与原结构差异 -> 预期作用。

写总体架构时，应先给出输入、输出、主干路径、跳跃或融合路径，再进入局部模块。写数学表达时，公式中的符号、张量维度、操作含义应能对应到结构图或文字说明。

### 7.3 核心模块

每个核心模块至少说明：

- 动机：原结构在哪个问题上不足。
- 设计：模块由哪些关键操作组成。
- 输入输出：输入特征、输出特征及维度或语义变化。
- 信息流：哪些信息被增强、筛选、融合或传递。
- 数学含义：公式符号与计算步骤的对应关系。
- 对比：相较原结构增加、删除或改变了什么。
- 预期改善：预期影响哪些指标、现象或失败类型。

### 7.4 Thesis-as-primary-narrative principle

正式方法章不是文献审计或来源恢复报告。方法事实应直接写成“本文提出……”“网络采用……”或“特征经过……”，使本文及正式方法名称成为叙述主体；不得写成“某内部论文说本文方法……”“来源没有说明所以本文不……”或“为了保持 evidence boundary……”。

证据核验发生在 Source Packet、Author Notes 与 supervisor review。进入正式正文的只能是已经核验后的学术结论；存在 source gap 时，执行 `OMIT IN BODY`，必要时仅保留 `%（作者核验备注：……）`，而不向读者解释 gap reasoning。

方法段落首先回答方法是什么、如何实现、为何采用该设计以及信息如何流动。段落的主要功能必须是技术解释或论证，而不是说明本段为何不讨论其他内容。

## 8. 实验章节五层证据链

实验章不是一张总表，而是回答研究问题的证据系统。五层证据链如下：

- 总体有效：与基线和代表性方法比较，证明方法整体有竞争力。
- 模块有效：通过消融证明关键模块不是装饰。
- 机制合理：通过可视化、边界分析、类别分析或中间特征解释为什么有效。
- 稳定可靠：通过多次运行、跨数据集、鲁棒性分析或方差分析降低偶然性。
- 工程/统计可靠：报告参数量、FLOPs、推理时间、显存、统计检验或置信证据。

证据强度应与结论强度匹配。越强的结论，需要越完整的证据链。

### 8.1 Hidden evidence-audit and result-caveat principles

实验正文只呈现核验后的实验设置、结果与分析，不复述 Source Packet、Author Notes 或审核中的来源冲突、证据身份和治理判断。信息缺口直接从正文省略，或以 `%（作者核验备注：……）` 留给作者核验。

统计检验缺失、benchmark 范围有限或可视化样本有限等真实限制，可以在最相关的结果或讨论位置集中说明。限制应表述为科学上的适用范围或证据局限，不得在每个结果段重复写成来源审计或写作安排说明。

## 9. 结果分析规则

禁止只读表格。每张核心表至少分析：

- 最重要现象是什么。
- 量化差异是多少。
- 可能原因是什么。
- 该现象与方法设计有什么关系。
- 是否支持原研究假设。
- 是否存在代价、例外或边界条件。

结果分析应把数字、结构设计和研究问题连接起来。不能只写“本文方法取得最佳结果”或“说明方法有效”。

## 10. 消融实验规则

消融实验不只说明 A/B “有效”，还要解释不同模块分别贡献什么能力以及是否互补。

推荐结构：

- Baseline：作为无新增设计的比较锚点。
- Baseline + A：分析 A 主要改善的指标、类别或现象。
- Baseline + B：分析 B 主要改善的另一类能力或约束。
- Baseline + A + B：分析组合是否进一步提升，是否存在互补、冗余或代价。

若模块提升不一致，应如实解释可能原因，不强行包装为全面有效。

## 11. 可视化与失败案例规则

可视化服务于机制解释和局限分析，不作为装饰。

至少考虑以下类型：

- 典型成功样本：展示方法相对基线的主要优势。
- 困难样本：展示边界模糊、小目标、低对比度、噪声或形态变化下的表现。
- 必要时失败样本：说明模型仍然可能出错的区域和原因。
- 机制可视化：使用注意力图、中间特征、边界图、类别热区或其他可解释材料支撑模块作用。

失败案例应进入展望，成为真实改进方向的证据来源。

## 12. 本章小结规则

本章小结按“问题 -> 方法 -> 证据 -> 结论”组织。

禁止按 3.1、3.2、3.3 重新复述目录。小结应回收本章试图解决的问题、采用的方法、实验证据或理论分析，以及得到的有限结论。

## 13. 总结与展望规则

总结必须与第一章“本文主要研究内容”形成镜像。

- 第一章承诺解决的问题，应在总结中按同一顺序回应。
- 每项研究内容都要对应方法、主要结果和结论边界。
- 总结中的数值、指标和结论必须与实验章一致。

展望必须来自：

- 真实实验局限。
- 真实方法局限。
- 真实失败案例。

不得只写“扩大数据集”“提高精度”“探索更多应用”。展望应说明当前证据暴露了什么问题、为什么该问题尚未解决、下一步可如何验证或改进。

## 14. 图表规则

图和表必须对应研究问题，不能只作为装饰。

- 结构图回答“方法如何工作”。
- 结果表回答“是否有效、在哪些方面有效、代价是什么”。
- 消融表回答“模块分别贡献什么、是否互补”。
- 可视化图回答“为什么有效、在哪些条件下失败”。
- 效率表回答“是否满足工程约束”。

图表标题、正文分析和研究问题应相互对应。

## 15. 章节完成自检清单

完成每章后检查：

- 本章是否承担了总体论证链中的明确任务？
- 每段是否只有一个主要论证功能？
- 是否先解释问题，再介绍方法或模块？
- 研究现状是否按技术路线和问题组织，而不是按作者年份罗列？
- “现有不足”是否能被后续方法和实验回应？
- 双工作关系是否达到核心机制继承式或问题层次升级式？
- 第二章是否只铺垫后续真正使用的理论？
- 方法章是否说明了总体架构、数据流、核心模块、数学表达、结构差异和预期作用？
- 每个核心模块是否写清动机、设计、输入输出、信息流、数学含义、对比和预期改善？
- 实验章是否形成总体有效、模块有效、机制合理、稳定可靠、工程/统计可靠五层证据链？
- 每张核心表是否分析了现象、差异、原因、设计关系、假设支持和代价例外？
- 消融是否解释模块能力与互补性？
- 可视化是否包含成功、困难、必要失败和机制解释材料？
- 本章小结是否按“问题 -> 方法 -> 证据 -> 结论”写成？
- 总结是否镜像第一章研究内容？
- 展望是否来自真实局限或失败案例？
- 所有强结论是否能追溯到 `docs/FACTS_AND_NUMBERS.md` 的证据？
- 是否避免了参考论文连续原文、模板化过渡、空洞强化词和无证据的“显著”？
